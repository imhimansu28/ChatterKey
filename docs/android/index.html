A keyboard first. Voice when you want it.

ChatterKey is a native Android input method, not a web page you have to copy from. The default English (India) layout includes staggered QWERTY, a wide spacebar, Shift/caps lock, two number/symbol pages with ₹, long-press top-row digits and repeat Backspace.

  • Hold the mic: speak, then release to process. Double-tap for hands-free and tap again or use Stop to finish. Cancel clears the attempt.
  • See the recording state: local audio-level animation, a timer and separate processing feedback. Audio is limited to two minutes in memory.
  • Choose the writing mode: use a professional, concise, technical, bullets, translation or other available mode, with your own vocabulary and instructions.
  • Keep typing offline: ordinary key taps don’t need a provider key or internet. AI dictation and voice edits do.

One audio-capable model handles each attempt through Google Direct or optional OpenRouter. There’s no separate transcription/polishing request chain, hidden automatic retry or automatic Send.

How to install and enable the keyboard.

  1. Check your phone. The signed APK supports ARM64 phones on Android 9/API 28 or later. It is not a 32-bit/x86, iPhone or emulator build.
  2. Get the release APK. Use the Android download section and its checksum. If you previously used a debug build, read the migration warning below before installing.
  3. Install intentionally. Open the APK in Android’s installer. If prompted, allow installation only from the source you chose; don’t disable device security globally.
  4. Enable ChatterKey. Open the app → Practice → Enable ChatterKey → Choose keyboard. Android shows its standard third-party keyboard warning. Review the privacy information before enabling it.
  5. Connect voice processing. Allow microphone access. In Settings, choose Google Direct or OpenRouter, enter that provider’s API key and an available audio-capable model, then Save.
  6. Try the private Practice editor. Test typing, hold/release, double-tap/Stop, Cancel and a selected-text edit using sample text. Practice intentionally doesn’t contribute to usage counters.

Already used the debug APK? Debug and release signing identities differ. Safely save your key and important preferences, then remove old debug ChatterKey copies from every profile where installed—including secondary/work/secure/clone spaces. Remove only ChatterKey, not a whole profile. Uninstalling removes that copy’s local data.

Edit a selection. Not the whole conversation.

Select an editable passage in the current app, then record the change you want. ChatterKey shows the original and proposed text, local edit highlights and protected-value warnings.

Apply requires the original editor session, selection and nearby context to remain verifiable. If the target changes or the app provides incomplete information, use Copy instead. Nearby context is checked locally, not added to the provider’s edit request.

Voice insertion never invokes Send or Enter. The keyboard’s separately pressed manual action key can still send when the host app requests that action. Review the result before using it.

Local counters. Only if you opt in.

Dashboard has optional daily, seven-day and all-time aggregate counters. They start off. Typed-word runs are estimates from accepted ChatterKey typing—not an exact count of the document. Voice output counts words in the final result, not exact spoken words. Voice edits are counted separately.

Counters store no typed text, audio or per-attempt history and add no model request. Password/unsupported fields, private-marked editors and Practice are excluded. Correct private-field detection depends on the host app. Clear Usage or changing consent invalidates pending counts.

Provider keys are encrypted with Android Keystore and separated by provider. App backup/cloud transfer is disabled. Audio is held in memory for an attempt and possible explicit Retry; hiding or switching the keyboard cancels active recording/processing. Final voice processing still sends audio to your selected provider.

Read the full privacy details. Mac history, cost dashboards and automatic key/settings sync are not part of this Android release.

Installation conflicts and honest limits.

“Package conflicts with an existing package.”

An old debug-signed copy can remain in another Android profile even after removal from the main one. Check all profiles for ChatterKey, preserve important preferences, and remove conflicting debug copies before the first release install. Future ordinary release updates use the same release key and a higher version code; they should not require uninstalling.

Microphone permission was denied.

Use the offered app-settings recovery to review Microphone permission. Check the provider connection and model if recording works but processing fails. Retry stays explicit; it is not an automatic fallback.

What isn’t included yet?

Predictive/swipe typing, a dedicated Hindi layout, local live transcription, transcript history and a billing/cost dashboard aren’t included. Hindi/Hinglish voice results depend on the model and selected writing instructions.

The signed release’s USB installation and launch were checked on one Android 15 ARM64 phone. Earlier debug UI/core fixtures passed, but live release-mode microphone, provider, editor and lifecycle coverage is incomplete. See the Android 1.0.0 release notes for scope, and the separate Mac dictation app for desktop features.
